# 接口

这份文档描述仓库里已经提交的文件。属性名、函数参数和更新列表都以这些文件为准。

## 1. Flake 输出

`flake.nix` 只有一个输入：

```nix
inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
```

`outputs` 的参数是 `{ self, nixpkgs }`。系统只有 `x86_64-linux`。导入 nixpkgs 时设置了 `config.allowUnfree = true`，这样本 flake 的 `packages` 和 `checks` 可以求值专有包。

| 输出 | 内容 |
| --- | --- |
| `packages.x86_64-linux.<name>` | `default.nix` 里的每个属性。名字见下一节 |
| `overlays.default` | `final: prev:`，等于 `import ./default.nix { pkgs = prev; }`。`overlay.nix` 是同一份函数，flake 直接把逻辑写在 `flake.nix` 里，`overlay.nix` 给非 flake 的 `import` 用 |
| `checks.x86_64-linux.package-<name>` | 和 `packages.x86_64-linux.<name>` 是同一个 derivation。`<name>` 里的连字符保留，例如 `checks.x86_64-linux.package-grub-theme-dedsec` |

没有 `nixosModules`，也没有 devShell。

给同样钉在 nixos-26.05 的配置引用：

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
    nur-packages.url = "github:JimmyWang0417/nur-packages";
    nur-packages.inputs.nixpkgs.follows = "nixpkgs";
  };

  outputs = { nixpkgs, nur-packages, ... }: {
    nixosConfigurations.example = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ({ pkgs, ... }: {
          nixpkgs.config.allowUnfree = true;
          nixpkgs.overlays = [ nur-packages.overlays.default ];
          environment.systemPackages = [ pkgs.animeko pkgs.crm ];
        })
      ];
    };
  };
}
```

调用方在自己的 flake `inputs` 里加入 `nur-packages`，并在 NixOS module 里设置 `nixpkgs.overlays`。专有包不打开 `allowUnfree` 时，overlay 一应用就会在求值阶段失败。

单包构建不经过系统配置：

```bash
nix --extra-experimental-features 'nix-command flakes' build --no-link .#animeko
```

`--no-link` 避免在主目录留下 `result` 符号链接。

## 2. Overlay 里的包

`default.nix` 的签名是 `{ pkgs }:`。它只做 `pkgs.callPackage ./pkgs/<name> { }`。overlay 把 `prev` 传进这个 `pkgs`。包函数自己的参数由 `callPackage` 从 nixpkgs 填入，下面每一节的花括号就是那个函数的完整参数表。

- 许可：`lib.licenses.unfree`，调用方须允许 unfree。应用本仓库 overlay 会替换 nixpkgs 同名正式版 `pkgs.typora`，不要把两者装入同一 profile
- 更新：`updates.nix` 的 `kind = "typora-plugin"` 仅更新插件，保持编辑器免费 beta 固定；先构建和检查，再由工作流提交并推送到 `main`。每日 `github-rev` 筛选不处理该项
- 详细说明：[Typora 使用与维护文档](typora.md)

## 3. 再加一个包

1. 新建 `pkgs/<name>/default.nix`。这个文件是一个函数，参数由 `callPackage` 注入。现有包都不是 `pkgs: { ... }` 那种一层函数。
2. 在 `default.nix` 加一行：

```nix
<name> = pkgs.callPackage ./pkgs/<name> { };
```

`callPackage` 的调用形式固定是 `pkgs.callPackage ./pkgs/<name> { }`。花括号是留给显式覆盖的，现在每个包都传空集。包函数的形参必须是 nixpkgs 里已有的名字，例如 `{ lib, stdenv, fetchurl }: stdenv.mkDerivation { ... }`。

3. 不需要改 `overlay.nix` 或 `flake.nix`。两者都是 `import ./default.nix { pkgs = ...; }`，新属性会同时出现在 `packages.x86_64-linux.<name>`、`overlays.default` 和 `checks.x86_64-linux.package-<name>`。
4. `.github/workflows/ci.yml` 不写死包名。它求值 `packages.x86_64-linux` 的全部属性名，再 `nix build`。新包只要出现在 `default.nix` 里就会被 CI 构建。
5. 周更不会自动跟上。要跟上，必须再往 `updates.nix` 的列表里加一项。见下一节。`kind = "github-rev"` 走同一份工作流的每天 16:00 UTC，不另建工作流。

`final: prev:` 只出现在 overlay。包函数不要写成 `final: prev:`。

## 4. 更新接口

允许被周更的包只写在 `updates.nix`。这是一个 Nix 列表，每一项都是字符串字段：

| 字段 | 含义 |
| --- | --- |
| `attribute` | flake 属性名，例如 `animeko` |
| `file` | 要改写的 nix 文件，相对仓库根 |
| `owner` / `repo` | GitHub 仓库 |
| `kind` | `github-asset`、`github-source`、`github-rev`、`typora-plugin` 或 `http-version` |
| `asset` | `github-asset` 或 `typora-plugin` 的发布文件名。`{version}` 会被替换。`github-source` 和 `github-rev` 留空字符串 |

当前列表：

| --- | --- | --- |

| `botmux` | `github-asset` | `botmux-linux-x64` |
| `xjtutoolbox` | `github-asset` | `XJTUToolbox-linux-x86_64.AppImage` |
| `xjtu-course-genius` | `github-asset` | `XJTU-Course-Genius-linux-x64.deb` |
| `crm` | `github-source` | tag `v<version>` 的 `fetchFromGitHub`，并重写 `pkgs/crm/Cargo.lock` |
| `grub-theme-dedsec` | `github-rev` | 默认分支 HEAD。rev 变了才改写 `rev` 和 `hash` |
| `tela-icon-theme` | `github-rev` | 默认分支 HEAD。rev 变了才改写 `rev` 和 `hash` |

| `typora` | `typora-plugin` | 插件最新 release 的 `typora-plugin@v{version}.zip`；编辑器固定为 0.11.18 |

`.github/workflows/update.yml`：

- 触发：`workflow_dispatch`，每周一 04:17 UTC（`17 4 * * 1`），以及每天 16:00 UTC（`0 16 * * *`）
- 权限：`contents: write`，用默认 `GITHUB_TOKEN`
- 输入：仓库工作树，以及 `updates.nix`。每天 16:00 UTC 那一次把 `UPDATE_KINDS=github-rev,http-version` 传给脚本。手动触发和周一那一次不设 `UPDATE_KINDS`，处理列表里的全部项
- 步骤：`cachix/install-nix-action@v31`，然后 `python3 ./scripts/update.py`
- `scripts/update.py` 用 `nix eval --file ./updates.nix --json` 读列表。`github-asset` 和 `github-source` 请求 `https://api.github.com/repos/<owner>/<repo>/releases/latest`，去掉 tag 开头的一个 `v` 得到版本。版本没变就跳过。设置了 `GITHUB_TOKEN` 时，GitHub API 请求带 `Authorization: Bearer`，避免 Actions 共用未认证限额
- `github-asset`：`nix store prefetch-file` 下载 `https://github.com/<owner>/<repo>/releases/download/v<version>/<asset>`，把该文件里第一处 `version = "..."` 和第一处 `hash = "sha256-..."` 换成新值
- `github-source`：`nix flake prefetch github:<owner>/<repo>/v<version>` 得到源码哈希，同样替换第一处 `version` 和 `hash`，然后在该 tag 上跑 `cargo generate-lockfile`，覆盖旁边的 `Cargo.lock`。`crm` 没有单独的 `cargoHash`，因为 `cargoLock.lockFile = ./Cargo.lock`
- `github-rev`：请求 `https://api.github.com/repos/<owner>/<repo>/commits/HEAD`。返回的 SHA 和文件里每一处 `rev` 都相同就跳过，已有的 `hash` 不动。有任一处不同，就用 `nix flake prefetch github:<owner>/<repo>/<rev>` 把每一处 `rev` 和每一处 `hash` 改成这个 HEAD，并改写 `version = "0-unstable-YYYY-MM-DD"` 的日期。`rev` 和 `hash` 的数量必须相同
- `http-version`：有 `versionPattern` 时 GET `versionUrl`，用第一个捕获组当版本。否则 HEAD `versionUrl` 并读取 `versionHeader`。版本变了才用 `fileUrl`（`{version}` 会替换）预取并改写该文件第一处 `version` 和第一处 `hash`
- `typora-plugin`：请求插件最新 release，保留实际 tag（有或没有 `v`），要求存在匹配的发布 ZIP，并重新预取 SHA-256；仅改 `pkgs/typora/sources.nix` 的 `pluginVersion` 与 `plugin` 下载块，不改编辑器版本和两架构的 Typora URL/散列。来源改变后，工作流先构建 `typora` 和布局、启动器、GUI 检查，再提交到 `main`
- 输出：工作树里被改过的 nix 文件和可能的 `Cargo.lock`。没有改动时脚本打印 `no upstream changes`，工作流结束，不提交
- 有改动时，工作流只 `git add -- pkgs`，提交，再 `git push origin HEAD:main`。命令里没有 `--force`。推送不是快进时这次运行失败，不会覆盖 `main`

新包要加入更新，就在 `updates.nix` 追加一项。`kind` 只能是上面列出的字符串。`github-asset` 的 nix 文件必须正好有一处 `version = "..."` 和一处 `hash = "sha256-..."`，否则脚本退出非零。`github-rev` 至少要有一处 `rev = "<40 位十六进制>"`，并且 `hash = "sha256-..."` 的数量要和 `rev` 相同。不在列表里的包不会被改写。`whitesur-kde` 在列表里，壁纸和边框共用这一对 `rev` / `hash`。

## 5. 故意不是输入的东西

这些不会出现在 `flake.nix` 的 `inputs`、`default.nix` 或 `updates.nix` 里：

- 密钥、age key、`.directory`、`.env`
- 原样复制的 AUR PKGBUILD
- 宿主机 EasyConnect 客户端（官方 deb）。容器镜像是 `docker-easyconnect`，不是这份 deb
- `github:Hobr/my-nix` 整份 flake
